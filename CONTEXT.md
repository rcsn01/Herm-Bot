# Hermes Mobile — Domain Glossary

Terms used across the mobile repository. Add new concepts here when a refactor names something that didn't have a word.

- **Gateway** — the remote Hermes backend the app talks to (JSON-RPC over WebSocket for prompts/events, native HTTP for REST/uploads). Identified by a `remoteURL` + `profile` pair.
- **Profile** — an isolated Hermes instance on the gateway; the app scopes all state and queries to one profile at a time.
- **Scope** — the (connection, profile) pair captured when an async operation starts; results from a stale scope are discarded.
- **Scoped operation** — an async operation that captures the Scope when it starts and discards its effects if the Scope changed before it lands. `gateway/scope-guard.ts` — the scoped-operation toolkit — owns capture (`currentGatewayScope()`), the staleness check (`isCurrentGatewayScope()`), and the guard plumbing: `beginScopedTask()` hands manual async operations a capture-plus-`isCurrent()` guard, and `useScopedMutation(...)` wraps react-query mutations so their callbacks run only while the Scope is current (with an optional `optimistic` contract owning cancel → snapshot → apply → rollback → invalidate). Call-site *policy* (commit/cleanup/retry/error display) stays in caller callbacks; the capture/check plumbing lives in the toolkit.
- **Scoped mutation** — a react-query mutation built through `useScopedMutation`; its callbacks are invoked only when the captured Scope is still current at landing time.
- **Scoped query** — a react-query query built through `useScopedQuery(key, { queryFn })` over a cache key derived by `useScopeKey(domain, parts)`; the toolkit keys the cache by the active connection/profile (`unscoped` pins the key to the connection), classifies failures into a `GatewayError` at the interface so callers render without re-classifying and the shared retry policy sees retryable kinds, and `useScopeReset(reset, ...extraDeps)` owns the scope-change reset idiom for call-site local state. Route vocabulary (domain, parts, fetcher, gates) stays with the call site; error rendering goes through the shared `GatewayErrorBanner` (`gateway/gateway-error-banner.tsx`).
- **Scoped task** — a manual async operation guarded by `beginScopedTask().isCurrent()`. Two forms: the raw capture (for long-lived effects and engine parameterization such as `isCurrentScope:` feeds) and the managed runner `useScopedTask()` in `gateway/scope-guard.ts`, which owns the choreography — Scope capture, stale-effect discard, error classification — and invokes `onError(classified GatewayError)`, `onBusy(true/false)`, and `onSettled` only while the Scope is current. Call-site policy (what to display, which busy flag, mid-run gating via the passed task handle) stays in the body and callbacks. `run` resolves `undefined` when the Scope went stale or the body threw.
- **GatewaySession** — the deep module between `GatewayController` and the wire. Owns both transports (WebSocket JSON-RPC client + native HTTP plugin), error classification, scope/epoch guarding, and the session lifecycle (open, resume, create, branch, history). Session history methods return raw gateway rows plus pagination metadata; Transcript owns their meaning. Interface: `GatewayPort` plus the session lifecycle methods.
- **Gateway API (profile-bound)** — the deep module between the feature API modules and the wire. `createGatewayApi(gateway, profile)` binds a GatewayPort to the active Profile and owns profile-path derivation (`?profile=` on scoped routes), response unwrapping, the deliberately-unscoped route tier (billing RPCs, `/api/actions/{name}/status`, provider OAuth poll/cancel, MCP OAuth poll/cancel, `/api/status`), and the default-profile gate. Provider and MCP start routes, plus memory-provider OAuth start/status routes, remain profile-scoped. Feature APIs (`createCronApi(api)`, `createSettingsApi(api)`, …) are thin route vocabulary over it; Scope staleness and error classification stay with the GatewaySession.
- **Sessions API** — the feature API between the GatewayController (and the settings archived-chats screen) and the wire for session list + mutation route vocabulary. `createSessionsApi(api)` over the profile-bound Gateway API owns the `/api/sessions` routes (list via `session.list` RPC, rename/archive/restore/delete) and nothing else: Scope capture, effect discard, bookmarks, and query orchestration stay with the GatewayController; staleness and classification stay with the GatewaySession. Wire shapes are byte-stable — PATCH carries `profile` in the body (via `api.profileKey`), DELETE does not — until the backend contract says otherwise.
- **Files API** — the feature API between the Projects screen (files/git/artifacts panels) and the wire for remote-file work. `createFilesApi(api)` over the profile-bound Gateway API owns the `/api/files*`, `/api/git/*`, and `/api/fs` route vocabulary, the upload policy (JSON `data_url` body, 50 MB cap, destination path joining), and profile-bound download/share options; `list` normalizes the legacy `entries|files` body shapes. View generations, confirm dialogs, and rendering stay with the Projects screen; staleness and classification stay with the GatewaySession. Chat audio (`/api/audio/*`) is chat-surface vocabulary and rides the GatewayPort directly, not this module.
- **Gateway action** — a long-running operation the gateway starts asynchronously: the start route returns a poll handle, and `/api/actions/<handle>/status` reports `running` or a final exit code. The remote-action module (`gateway/remote-action.ts`) owns both the engine (backoff, abort, Scope predicate, network-error retry) and this protocol: `runGatewayAction(api, { start })` asserts the start, polls the deliberately-unscoped status route, maps terminal status, and rejects with a `GatewayError` when the action fails. Feature APIs keep only the start route as vocabulary. OAuth flows are a different wire protocol and are owned by the OAuth flow module (`gateway/oauth-flow.ts`), which parameterizes the same engine.
- **OAuth flow** — a provider, memory-provider, or MCP-server authorization tracked by the gateway. Provider and MCP flows expose an opaque session/flow handle; memory-provider OAuth is status-only and exposes no handle, authorization URL, or cancel route. The OAuth flow module (`gateway/oauth-flow.ts`) owns the protocol end to end: start, open an authorization URL when supplied, poll the status route, map wire states to normalized phases (waiting / approved / denied / expired / error), and classify poll exhaustion as a `GatewayError` (`OAUTH_TIMEOUT`). Flow vocabulary (start/poll/phase adapters over the feature APIs) lives with each feature; Scope capture and stale discard live in the module; cancel routes and device-code submit stay call-site policy. Shares the `runRemoteAction` engine with the Gateway action protocol.
- **RuntimeSession** — a live session handle returned by the gateway (`session_id` + `stored_session_id` + contract info) with unprojected history rows.
- **Transcript** — the deep in-process module that turns gateway `SessionMessage` rows and transcript-specific live events into an immutable semantic snapshot. Owns compatibility normalization, row identity, activity/tool/cron classification, loaded user ordinals, durable edit targets, prepend deduplication, and latest-page reconciliation. Its interface is `createTranscript` plus `updateTranscript`; policy helpers remain private in `transcript/transcript.ts`.
- **Conversation** — the deep module between the UI and the GatewaySession's chat surface. Owns the active session's chat state end to end: the `$chat` atom and its Transcript snapshot, gateway-event reduction, prompt submission (send / queue / interrupt / steer / redirect / retry-from), interactive-prompt responses, attachments, and transcript history orchestration (reconcile + paging, including the reconcile-on-`message.complete` policy). Lives in `state/conversation.ts`; constructed and driven by the GatewayController, which forwards runtime events to it. The Session selection module owns *which* session is live; the Conversation owns session *content* (what the transcript shows). The sole writer of `$chat`.
- **Session selection** — the deep module in `state/session-selection.ts` for which session is live. Owns the selection epoch (the request-epoch idiom over user-initiated selections — create / resume / branch / latest), the Scope-guarded publish of a selected session (source lookup from `$sessions`, adoption through the Conversation — which stays `$chat`'s sole writer — the session-bookmark write, and the per-verb follow-up policy: create refreshes the list best-effort, branch awaits and rethrows, resume awaits reconcile), the `latest` roster-tap pick (newest human session, warm-tap freshen-or-skip, resume-failure → create fallback), and the connect/reconnect `restore` path (target resolution `$chat.storedSessionId ?? bookmark`, clear-if-not-resumed, adopt; publish guarded by the captured Scope plus the controller's reconnect epoch, so an automatic reconnect never supersedes an in-flight user selection). The read-only predicates (`activeStoredSessionId`, `hasLiveSession`) are the sanctioned `$chat` reads outside the Conversation. Transport lifecycle, connection phases, and session-list paging stay with the GatewayController; session mutations (rename/archive/delete) stay out until the session mutation workflow deepens.
- **Chat state (`$chat`)** — the nanostores atom holding the active session's Transcript snapshot, running flag, pending prompt, and history paging. Owned by the Conversation module (`state/conversation.ts`), which is its only writer; UI reads semantic entries via `useStore($chat)` and does not interpret gateway rows.
- **Session bookmark** — the per-scope localStorage pointer to the last opened durable session. Owned by the Session selection module: written when a session with a stored id is published, resolved as the restore target (`$chat.storedSessionId ?? bookmark`) by connect/reconnect, cleared when a restore with a candidate id lands on a fresh session.
- **Request epoch** — a module-local generation counter guarding against a *newer user action* superseding an in-flight operation (files-screen's `viewGeneration`). Distinct from the Scope: it discards superseded requests, not stale-scope results.
- **Lifecycle epoch** — a module-local generation counter guarding a module's own long-lived cycle (the GatewayController's reconnect generation, the DeepLinkCoordinator's pending intents). Distinct from the global Scope generation, which tracks connection/profile changes.
- **Model editing** — the deep module between the Models screen and `ModelsApi` for model-changing work. It owns main assignment confirmation, auxiliary assignment, profile-default config persistence, Scope guards, per-field write order, optimistic cache updates, rollback, and invalidation. The screen owns rendering and local form drafts; `MoaEditor` owns MoA preset persistence.
- **Settings autosave** — the deep module in `features/settings/use-config-autosave.ts` for schema-backed profile-default fields. It owns debounce, global-within-screen write order, confirmed baselines, optimistic config-cache updates, rollback, error classification, invalidation, abort, and Scope/category lifecycle. `ConfigSectionScreen` owns config and schema queries, category selection, schema interpretation, and rendering; `SettingsApi.savePartial` remains the remote adapter seam. Model editing keeps its separate persistence policy and query key.
- **Profile workflow** — the deep module for Profile creation, seeded duplication, and editing (`features/agents/profile-workflow.ts`, with the React entry in `features/agents/use-profile-workflow.ts`). It owns payload mapping, advanced and avatar loading, operation ordering, expensive-model confirmation, Scope and dialog-generation guards, create partial-save warnings, edit failure policy, and roster refresh. The dialogs own rendering and local drafts; `AgentsApi` remains the RPC adapter seam. Profile deletion stays outside this module.
- **Group chat** — a room where the user and 2–6 bot profiles share one ordered log, ported from the desktop Bot Mode. The desktop owns rooms in plugin storage and mirrors a bounded display copy; this PWA keeps a local working copy whose watermarks, member plumbing-session ids, stop holds, stranded markers, and room epoch are local coordination state and never ride the wire. A member is reached through the Group lifecycle's captured transport with the member's profile riding the RPC params.
- **Group send engine** — the deep module behind group chats (`features/groups/`, interface in `group-engine.ts`). Owns the local room store and persistence, the mirror lifecycle, the round-robin drive (rounds, caps, responder rotation, continuation detection, hold application from user text, send/stop verbs, the drive finalizer — one member turn per boundary comes from the Group member turn module), the activity feed, and pending prompt mirroring. Interface: the lifecycle verbs (`startGroupEngine(transport)` / `stopGroupEngine()`), the room actions (`openGroupRoom`, `createGroupChat`, `sendToGroupChat`, `stopGroupThread`, `answerGroupPrompt`), and the read surface (`$groupChats`, `$groupActivity`, `$groupPrompts`, `$groupNeedsYou`, `$knownRooms`, `useGroupRooms(roster)`, `useKnownRooms()`, `publishRosterRooms`, `resetKnownRooms` — see Known rooms). The four state handles exported from `group-engine.ts` have the Nanostores `ReadableAtom` type, so TypeScript callers using this interface do not see `.set()`. Cross-feature UI tests create local rooms through existing Group engine actions, seed the retained roster through `publishRosterRooms` when exercising that read path or through gateway fixtures for gateway-backed UI rows, and assert behavior through caller-facing read paths rather than raw writable atoms. The raw writable atoms remain exported from `group-store.ts` for internal Group modules and Group-owned setup tests; direct cross-feature imports bypass this test convention, which is not runtime access control. `readonlyType` leaves runtime behavior unchanged, `ReadableAtom` still exposes `notify()` and `off()`, and values returned by `.get()` remain mutable. The GatewayController starts it on connect and stops it on scope teardown and dispose; each lifecycle captures a `GroupMemberGateway` for member turns and a separate mirror adapter from the injected transport. Which room to open and what to draft stay with the screens.
- **Member key** — the one member identity inside a room (`group-model.ts` `groupMemberKey`): `${connectionId}::${name}` when the member row carries a connectionId, bare name otherwise. It keys the engine's local coordination state (holds, watermarks as `${thread}::${key}`, plumbing-session ids, stranded markers, pending prompts), the send engine's roster dedupe, and the mirror's member merge, so engine and mirror identity can never diverge. Mention resolution and room-log author attribution resolve through it. `sourceScoped` stays display/protocol vocabulary (the peer `[label]` suffix in turn prompts, the log entry's `source` label), never identity. Keys are computed locally from member rows and never ride the wire.
- **Room key** — the durable room identity shared by the engine and the mirror (`group-model.ts` `groupRoomKey`): `id:<roomId>` when the room carries a minted roomId (locally created rooms always do), `name:<name>` otherwise. It keys the engine's local room map, the runtime feed atoms (`$groupActivity`, `$groupPrompts` as `${roomKey}::${memberKey}`, `$groupNeedsYou`), the route parameter, and the mirror's snapshot, so a display-name rename only updates the room's `name` field for id-keyed rooms; the name-keyed class moves through one re-key sweep. Same string as `GroupRoom.key`.
- **Group member turn** — the deep module in `features/groups/group-turns.ts` for one member's turn end to end. Owns token ownership (capture, `commit()` lease, `TurnStoppedError` on lost ownership), the member's hidden plumbing session (resume/create, session-gone recovery), the submit/poll loop with deadline extension, clarify/approval prompt mirroring, the per-turn drive step (watermark delta and `${thread}::${memberKey}` keys, hold consumption, byte-faithful prompt assembly, turn indicator), that turn's room-log publication (activity, watermark advance, append with source labels, failure-reason visibility by policy), the stranded-marker invariant (a member with a standing marker takes no new turn; late replies are harvested), and the harvest itself. In-cluster interface: `takeTurn({ group, member, members, thread, driveEpoch, policy })` returning `{ abandoned, spoke, stop }` — `policy: 'round' | 'continuation'` carries the round driver's two publication policies (continuations hide failure reasons, bail on any room-epoch change before commit, and never inherit cross-thread acceptance) — plus `harvest(group, member)`, `harvestRoom(group, members)`, `answer`, `interrupt`, `stop`. `run` stays the module's internal test seam (raw turn result). The stranded-marker shape and its version map are invisible outside this module.
- **Group mirror** — the deep module in `features/groups/groups-sync.ts` for the bounded, display-oriented v3 snapshot under the default profile's `ui_meta['hermes-bots-groups']`. `createGroupMirror(gateway)` owns per-instance pull, scheduling, merge, CAS, read-back, retry, abort, startup hydration, and terminal stop policy. `GroupMirrorGateway` is the semantic adapter seam; the production adapter maps `profiles.list` and `profiles.configure` while the mirror stays independent of route names. Snapshots merge by durable room key, stable entry key, and tombstone, and sizes are charged by the gateway's JSON byte budget. The member-turn module uses its separate per-lifecycle `GroupMemberGateway` captured by the Group engine.
- **Known rooms** — the room list the UI renders: gateway roster snapshot rooms ∪ local engine rooms, unioned by durable room key (`id:<roomId>` or `name:<name>`; roster rows win a shared key — the gateway's richer copy), empty runtime tombstones filtered. Owned by the Group send engine's read surface in `group-engine.ts`: `$knownRooms` is a computed over the retained roster snapshot and `$groupChats`, so it recomputes on any room change whether or not a roster-carrying screen is mounted (the shell's always-mounted roster slot is not load-bearing for freshness). Roster-carrying screens (roster, group-room, create dialog) publish their query's groups through `useGroupRooms(roster.data?.groups ?? [])` — a content-signature publish (room keys + names; array identity never triggers a write) that returns that render's merged view synchronously; provider-free consumers read `useKnownRooms()`. `publishRosterRooms` / `resetKnownRooms` are the non-React publish/reset verbs (the reset clears only the roster half — the store owns rooms); the merge stays the pure `groupRoomsView`. Retention: the last roster snapshot outlives every roster screen.
- **Workspace navigation** — the deep module between the app shell and the route-stack store for everything route *policy* (`navigation/workspace-navigation.ts`, DOM-free core safe for the service-worker bundle; React entry in `navigation/use-workspace-navigation.ts`). Owns the workspace destination vocabulary (the bottom-nav destinations, including the `model` pseudo-destination that opens the settings-category route rather than a tab), destination titles, the cold-start screen-URL parse, the service-worker screen-path allowlist vocabulary (with the legacy served-only heads `/bot` and `/navigation`), and the menu/return-origin policy state (`$workspacePolicy`: menu latch, menu-origin capture, return-origin stack) held in the DOM-free core so non-React dispatchers resolve the same policy. Dispatch verbs live in the core: menu open/close and dismiss-intent resolution, destination taps (`openWorkspaceDestination`, `openGroupRoom`), `openChatSurface()` (roster agent entry, cron run → session, deep-link landing — clears the return origin and closes the latch), `openSettings()` (header gear: fresh settings root), `dismissForeground()` (committed foreground swipe), `back(source)` (the whole back tree — group-room, sessions, model-with-return-origin, then pop-or-exit; `source: 'header' | 'screen'` picks the no-origin fallback: the header falls to the roster, a menu-entered destination's screen back falls to the profile surface), and `resetWorkspace()` (scope teardown resets route stacks and policy together). The React entry is a thin adapter: `useWorkspaceNavigation()` exposes the verbs, the derived header model (destination, title, back label), foreground visibility/dismissibility, and the per-screen `screen(tab)` api (the tab's route narrowed with the root fallback, `back`, `navigate`; settings adds `showModelBack`). The route-stack store (`navigation-store.ts`) stays the engine; the sessions menu emits dismiss intents, the module resolves them. Which screen renders, wire calls, and dialogs stay with the app root.
- **Sessions menu** — the slide-over navigation page over a profile surface (session list, new session, bottom destination row). The Workspace navigation module owns its open/close latch and return-origin capture; the menu itself owns its session rows, its swipe-to-delete, and its scoped-task policy, and reports taps as dismiss intents instead of navigating directly.
