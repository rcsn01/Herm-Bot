# Hermes Mobile — Domain Glossary

Terms used across the mobile repository. Add new concepts here when a refactor names something that didn't have a word.

- **Gateway** — the remote Hermes backend the app talks to (JSON-RPC over WebSocket for prompts/events, native HTTP for REST/uploads). Identified by a `remoteURL` + `profile` pair.
- **Profile** — an isolated Hermes instance on the gateway; the app scopes all state and queries to one profile at a time.
- **Scope** — the (connection, profile) pair captured when an async operation starts; results from a stale scope are discarded.
- **Scoped operation** — an async operation that captures the Scope when it starts and discards its effects if the Scope changed before it lands. `gateway/scope-guard.ts` — the scoped-operation toolkit — owns capture (`currentGatewayScope()`), the staleness check (`isCurrentGatewayScope()`), and the guard plumbing: `beginScopedTask()` hands manual async operations a capture-plus-`isCurrent()` guard, and `useScopedMutation(...)` wraps react-query mutations so their callbacks run only while the Scope is current (with an optional `optimistic` contract owning cancel → snapshot → apply → rollback → invalidate). Call-site *policy* (commit/cleanup/retry/error display) stays in caller callbacks; the capture/check plumbing lives in the toolkit.
- **Scoped mutation** — a react-query mutation built through `useScopedMutation`; its callbacks are invoked only when the captured Scope is still current at landing time.
- **Scoped task** — a manual async operation guarded by `beginScopedTask().isCurrent()`. Two forms: the raw capture (for long-lived effects and engine parameterization such as `isCurrentScope:` feeds) and the managed runner `useScopedTask()` in `gateway/scope-guard.ts`, which owns the choreography — Scope capture, stale-effect discard, error classification — and invokes `onError(classified GatewayError)`, `onBusy(true/false)`, and `onSettled` only while the Scope is current. Call-site policy (what to display, which busy flag, mid-run gating via the passed task handle) stays in the body and callbacks. `run` resolves `undefined` when the Scope went stale or the body threw.
- **GatewaySession** — the deep module between `GatewayController` and the wire. Owns both transports (WebSocket JSON-RPC client + native HTTP plugin), error classification, scope/epoch guarding, and the session lifecycle (open, resume, create, branch, history). Interface: `GatewayPort` plus the session lifecycle methods.
- **Gateway API (profile-bound)** — the deep module between the feature API modules and the wire. `createGatewayApi(gateway, profile)` binds a GatewayPort to the active Profile and owns profile-path derivation (`?profile=` on scoped routes), response unwrapping, the deliberately-unscoped route tier (billing RPCs, `/api/actions/{name}/status`, OAuth flow/poll, `/api/status`), and the default-profile gate. Feature APIs (`createCronApi(api)`, `createSettingsApi(api)`, …) are thin route vocabulary over it; Scope staleness and error classification stay with the GatewaySession.
- **Sessions API** — the feature API between the GatewayController (and the settings archived-chats screen) and the wire for session list + mutation route vocabulary. `createSessionsApi(api)` over the profile-bound Gateway API owns the `/api/sessions` routes (list via `session.list` RPC, rename/archive/restore/delete) and nothing else: Scope capture, effect discard, bookmarks, and query orchestration stay with the GatewayController; staleness and classification stay with the GatewaySession. Wire shapes are byte-stable — PATCH carries `profile` in the body (via `api.profileKey`), DELETE does not — until the backend contract says otherwise.
- **Files API** — the feature API between the Projects screen (files/git/artifacts panels) and the wire for remote-file work. `createFilesApi(api)` over the profile-bound Gateway API owns the `/api/files*`, `/api/git/*`, and `/api/fs` route vocabulary, the upload policy (JSON `data_url` body, 50 MB cap, destination path joining), and profile-bound download/share options; `list` normalizes the legacy `entries|files` body shapes. View generations, confirm dialogs, and rendering stay with the Projects screen; staleness and classification stay with the GatewaySession. Chat audio (`/api/audio/*`) is chat-surface vocabulary and rides the GatewayPort directly, not this module.
- **Gateway action** — a long-running operation the gateway starts asynchronously: the start route returns a poll handle, and `/api/actions/<handle>/status` reports `running` or a final exit code. The remote-action module (`gateway/remote-action.ts`) owns both the engine (backoff, abort, Scope predicate, network-error retry) and this protocol: `runGatewayAction(api, { start })` asserts the start, polls the deliberately-unscoped status route, maps terminal status, and rejects with a `GatewayError` when the action fails. Feature APIs keep only the start route as vocabulary. OAuth flows are a different wire protocol and are owned by the OAuth flow module (`gateway/oauth-flow.ts`), which parameterizes the same engine.
- **OAuth flow** — a provider, memory-provider, or MCP-server authorization the gateway tracks as an opaque session/flow handle. The OAuth flow module (`gateway/oauth-flow.ts`) owns the protocol end to end: start, open the authorization URL externally, poll the status route, map wire states to normalized phases (waiting / approved / denied / expired / error), and classify the timeout as a `GatewayError` (`OAUTH_TIMEOUT`). Flow vocabulary (start/poll/phase adapters over the feature APIs) lives with each feature; Scope capture and stale discard live in the module; cancel routes and device-code submit stay call-site policy. Shares the `runRemoteAction` engine with the Gateway action protocol.
- **RuntimeSession** — a live session handle returned by the gateway (`session_id` + `stored_session_id` + contract info).
- **Transcript** — the rendered message list for a session, projected from gateway `SessionMessage`s via `toTranscript`.
- **Conversation** — the deep module between the UI and the GatewaySession's chat surface. Owns the active session's chat state end to end: the `$chat` atom, gateway-event reduction, prompt submission (send / queue / interrupt / steer / redirect / retry-from), interactive-prompt responses, attachments, and transcript history (reconcile + paging, including the reconcile-on-`message.complete` policy). Lives in `state/conversation.ts`; constructed and driven by the GatewayController, which forwards runtime events to it and owns session *selection* (which session is live) while the Conversation owns session *content* (what the transcript shows). The sole writer of `$chat`.
- **Chat state (`$chat`)** — the nanostores atom holding the active session's transcript, running flag, pending prompt, and history paging. Owned by the Conversation module (`state/conversation.ts`), which is its only writer; UI reads it via `useStore($chat)`.
- **Session bookmark** — the per-scope localStorage pointer to the last opened durable session.
- **Request epoch** — a module-local generation counter guarding against a *newer user action* superseding an in-flight operation (files-screen's `viewGeneration`). Distinct from the Scope: it discards superseded requests, not stale-scope results.
- **Lifecycle epoch** — a module-local generation counter guarding a module's own long-lived cycle (the GatewayController's reconnect generation, the DeepLinkCoordinator's pending intents). Distinct from the global Scope generation, which tracks connection/profile changes.
- **Model editing** — the deep module between the Models screen and `ModelsApi` for model-changing work. It owns main assignment confirmation, auxiliary assignment, profile-default config persistence, Scope guards, per-field write order, optimistic cache updates, rollback, and invalidation. The screen owns rendering and local form drafts; `MoaEditor` owns MoA preset persistence.
